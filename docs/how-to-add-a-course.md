# How to add a course

For whoever maintains Learning Support. Students cannot add or publish course content. They send a request, with files if they have them, and a course manager turns it into a course. The course itself is generated by the content pipeline on a laptop, not inside the app, because generating it in the app would need a paid AI API.

## Before you start

- You need a course manager account. Sign up in the app like a student, then the maintainer runs `python scripts/set_role.py <your email> course_manager`. A role can only be changed this way (or in SQL), never from the app.
- You need the repository set up as in `CLAUDE.md` ("Commands"): the `.venv`, and the service role key in `content/.env` and `scripts/.env`.
- Read `content/CLAUDE.md` once. It has the content rules: where facts may come from, the size of a sample course, and how past questions and links are handled.

## 1. Look at the request

1. In the app, open **Manage → Requests**. Each request shows the course code and title, the student, any lecturer or details they gave, and their files.
2. Click a file to download it. Links are signed and expire after 10 minutes.
3. If you are going to build the course, press **Mark in progress**. The student sees "In progress" and gets a notification.
4. If you cannot build it (for example, no such course exists, or there is no outline anywhere), press **Decline** and give a reason. The student sees the reason.

## 2. Collect the course files

1. Download the request's files into the pipeline's input folder:

   ```
   python scripts/course_requests.py               # lists open requests; note the first 8 characters of the id
   python scripts/course_requests.py files <id>    # saves them to content/sources/raw/requests/<CODE>/
   ```

2. Add anything else you have for the course, such as the department's shared Drive folder or past question papers, under `content/sources/raw/`. Nothing in `content/sources/` is committed.

## 3. Run the pipeline

From the repository root, with the `.venv` active (`source .venv/bin/activate`):

```
python content/ingest/inventory.py                  # finds the course and classifies its files
python content/ingest/extract.py --course "CSC 563" # pulls the text out of PDFs, slides and documents
```

Check `content/ingest/inventory.csv`. If a file was given the wrong code or kind, add a row to `content/ingest/inventory_fixes.csv` and run `inventory.py` again.

Then write the course files from `content/ingest/extracted/<code>/`, following `content/CLAUDE.md`. This is the step Claude Code does in the default mode, one course per run. The files are the course with its topics, a study note and practice questions per topic, past questions copied as written, and links. Mark the course `"is_reviewed": false`.

Publish it:

```
python content/ingest/publish.py --course "CSC 563"   # links, validation, then loading; nothing loads if validation fails
```

## 4. Check the course in the app

1. Open **Manage → Courses**. The new course appears under its level with a **Sample** label.
2. Open it and look through each topic: the title and summary, the links, and the practice questions with their answers.
3. Small fixes can be made right there: rename a topic, fix its summary, correct or hide a question, or add or fix a link. Every change is saved with your name in **Manage → Edit history**.
4. Make the same fix in the course's files too. Reloading a course from its files (`load.py` or `publish.py`) overwrites topic, question and link edits made in the app; `load.py` prints a warning listing them. Hidden questions, links added in the app and the reviewed mark are kept.
5. Press **Mark as reviewed** only after the content has been checked against the course's own files by someone who knows the course, ideally its lecturer. It removes the "Sample content, pending lecturer review" badge for students.

## 5. Tell the student

Back in **Manage → Requests**, press **Mark added** on the request and enter the course code. The student is enrolled in the course and gets a "course is ready" notification. You can do the same from the terminal:

```
python scripts/course_requests.py add <id> --course "CSC 563"
```

## Good to know

- Request files live in the private `course-request-files` bucket. Only the student who sent them and course managers can open them.
- A student can attach at most 5 files of 20 MB each: PDF, DOCX, PPTX or images.
- To see who is a course manager: `python scripts/set_role.py --list`. To take the role away: `python scripts/set_role.py <email> student`.
