# The SDLC: Phases, Models and CASE Tools

## The SDLC

The **systems development life cycle (SDLC)** is a **conceptual model describing the phases of an information system project**, from planning to maintenance. Considered the **oldest formalised methodology framework** (from the **1960s**), it gives a standard framework of activities and deliverables, aids planning and scheduling, makes tracking easier, improves visibility, and **reduces project risk and cost**.

## The seven phases

1. **Planning and feasibility study**: review and prioritise project requests, allocate resources and form the team. The **preliminary investigation** has three parts: **request clarification**, the **feasibility study** (technical, economic and operational) and **request approval**.
2. **Requirements analysis**: understand the business's goals, processes and constraints by asking what is done, how, how often and how well, using interviews, observation, questionnaires, and **data flow** and **context diagrams**.
3. **System design**: specify **how** the system will meet the requirements. **Logical design** describes what is needed; **physical design** describes the programs and hardware. Design begins by identifying the **outputs**.
4. **Development**: install purchased software or write custom programs.
5. **Testing**: use the system with test data, and sometimes a few users, to find failures before the organisation depends on it.
6. **Implementation**: install equipment and software, **train users** and build data files, then **evaluate** the system (operational evaluation, organisational impact, user assessment and development performance).
7. **Maintenance**: remove errors and tune the system over its working life.

## Changeover methods

- **Direct**: stop the old system completely and start the new one.
- **Parallel**: **run old and new side by side** until the new one is trusted (safest but costly).
- **Pilot**: try the new system in **one part** of the organisation first.
- **Phased**: introduce the new system gradually, part by part.

## SDLC models

- **Waterfall**: sequential phases, each completed once before the next.
- **Agile**: small incremental releases in short cycles, testing each iteration and relying on customer feedback, which can cause excessive scope changes.
- **Big Bang**: coding with little planning; suits small or practice projects.
- **Iterative**: start with a small set of requirements and repeatedly enhance a **working version**.
- **Incremental**: a "multi-waterfall" that builds the product in **modules**, each adding working functionality.
- **Spiral**: iterative with an emphasis on **risk analysis**, in four phases (**planning, risk analysis, engineering, evaluation**); the angular component shows progress and the radius shows cost.
- **Prototype**: build an early model for users to evaluate and refine requirements.

## CASE tools

**Computer-aided software engineering (CASE) tools** automate analysis and design tasks: drawing **DFDs** and diagrams, maintaining the **data dictionary**, checking DFD **balancing** and generating documentation and code.
