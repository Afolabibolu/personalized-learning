# Security Testing and Incident Response

## Security testing

**Security testing** is the process of **examining and evaluating computer systems, networks and applications to identify vulnerabilities, weaknesses and potential entry points** that attackers could exploit. Its goals are to:

- identify vulnerabilities;
- protect data and information;
- prevent unauthorised access;
- ensure system integrity;
- improve incident detection and response;
- test system resilience;
- verify that security controls work; and
- reduce security risks.

Its objectives are to detect vulnerabilities and gaps, prevent unauthorised access, protect sensitive data, ensure systems meet security standards and improve overall security.

## Types of security testing

- **Vulnerability testing**: identifies **known weaknesses** in systems and applications.
- **Penetration testing**: **simulates real cyber attacks** to test the system's defences.
- **Security auditing**: reviews security **policies, procedures and controls**.
- **Risk assessment**: evaluates potential **threats and their impact**.
- **Ethical hacking**: **authorised testing** by security professionals to find vulnerabilities before criminals do.

Security testing helps prevent attacks and breaches and strengthens defences. Some companies have penetration testing teams dedicated to finding and patching vulnerabilities, and third-party researchers do the same: **Google's Project Zero** is a permanent team formed to find software vulnerabilities.

## Incident response

No defence is perfect, so organisations need an **incident response plan**: a prepared set of steps for handling security incidents quickly and effectively. Security policies provide clear steps for **detecting, reporting and responding** to cyber incidents. A comprehensive plan defines the steps of:

1. **Detection** of the incident;
2. **Containment**, limiting its spread and damage;
3. **Eradication**, removing the cause, such as malware;
4. **Recovery**, restoring systems and data to normal operation; and
5. **Post-incident analysis**, learning lessons to improve defences.

The plan should be **tested regularly through simulated exercises** to improve readiness, and combined with **backup and disaster recovery planning** so that operations can continue during and after an incident.
